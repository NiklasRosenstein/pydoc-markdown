    Python API

    Everything the CLI does is available from Python, for use in your own build scripts.

    The full pipeline

    Class PydocMarkdown is the object a configuration file is loaded into. A fresh instance is preconfigured with a python loader, the filter, smart and crossref processors and a markdown renderer:

    from pydoc_markdown import PydocMarkdown
from pydoc_markdown.contrib.loaders.python import PythonLoader
from pydoc_markdown.contrib.renderers.markdown import MarkdownRenderer

session = PydocMarkdown()
assert isinstance(session.loaders[0], PythonLoader)
session.loaders[0].search_path = ["src"]

modules = session.load_modules()
session.process(modules)

assert isinstance(session.renderer, MarkdownRenderer)
print(session.renderer.render_to_string(modules))

    To start from a configuration file instead, load it and initialize the session with the file's directory as the context, so relative paths in it resolve the same way as on the command line:

    import os

from pydoc_markdown import PydocMarkdown
from pydoc_markdown.interfaces import Context

config_file = "docs/pydoc-markdown.yaml"
session = PydocMarkdown()
session.load_config(config_file)
session.init(Context(directory=os.path.dirname(os.path.abspath(config_file))))

modules = session.load_modules()
session.process(modules)
session.render(modules)

    load_config() also accepts a dictionary. Without the init() call, relative paths resolve from the current directory.

    Individual plugins

    Plugins can also be used on their own. Each one must be initialized with a Class Context first:

    from pydoc_markdown.contrib.loaders.python import PythonLoader
from pydoc_markdown.contrib.processors.smart import SmartProcessor
from pydoc_markdown.contrib.renderers.markdown import MarkdownRenderer
from pydoc_markdown.interfaces import Context

context = Context(directory=".")
loader = PythonLoader(search_path=["src"], packages=["my_package"])
processor = SmartProcessor()
renderer = MarkdownRenderer(render_module_header=False)
for plugin in (loader, processor, renderer):
    plugin.init(context)

modules = list(loader.load())
processor.process(modules, None)
print(renderer.render_to_string(modules))

    Note

    Without a filter processor, every member is rendered, including private and undocumented ones.

    Writing a plugin

    Loaders, processors, renderers and source linkers implement the interfaces in pydoc_markdown.interfaces. To make a plugin available by type name in configuration files, register it under the matching entry point group in your package's pyproject.toml:

    [project.entry-points."pydoc_markdown.interfaces.Processor"]
my-processor = "my_package.pydoc:MyProcessor"

    The groups are pydoc_markdown.interfaces.Loader, .Processor, .Renderer and .SourceLinker. Plugins are dataclasses; their fields become the options in the configuration file.
