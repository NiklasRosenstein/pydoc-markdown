    Changelog

    Unreleased

    Breaking changes

    • Drop Python 3.7 compatibility (@NiklasRosenstein) (#304)
    • Raise the minimum supported Python version to 3.10. (@NiklasRosenstein) (#355)

    Features

    • Add a pre-commit hook for pydoc-markdown. (@RomainTT) (#298)
    • Add the escape_curly_braces_in_docstring Markdown renderer option to escape { and } for MDX v2+ (e.g. Docusaurus v3). (issue #325, @nonprofittechy) (#326)
    • Allow setting a fallback page title for standalone Markdown rendering. (@NiklasRosenstein) (#356)
    • Allow renderer pages to exclude API objects with glob patterns. (@NiklasRosenstein) (#358)
    • Support NumPy-style docstrings and explicit docstring style selection in the Sphinx processor. (issue #251, @NiklasRosenstein) (#360)

    Improvements

    • Bump minimum version of databind.core and databind.json to ^4.4.2 to ensure Python 3.12 support (@NiklasRosenstein) (#304)
    • Replace Black and isort development checks with Ruff and restore mypy compatibility across the supported Python matrix. (@NiklasRosenstein) (#354)
    • Make automatically discovered module ordering deterministic. (@NiklasRosenstein) (#356)
    • Deprecate the Novella integration; it now emits a FutureWarning and will be removed in a future major release. (@NiklasRosenstein) Deprecate the --py2/--py3 flags, which have no effect with the current parser; they now print a warning and no longer disable loading the configuration file. (@NiklasRosenstein) (#384)
    • --bootstrap now writes pydoc-markdown.yaml instead of pydoc-markdown.yml. Both names are still loaded. (@NiklasRosenstein) (#386)

    Fixes

    • Fix escape_except_blockquotes option for greater than 9 blockquotes in a docstring (@jackgerrits) (#317)
    • Use consolidated Databind, exclude the broken 4.5.2 proxy packages, and require TypeAPI 2.3.0 to keep configuration loading compatible across supported Python versions. (@NiklasRosenstein) (#355)
    • Watch configured page source files when serving MkDocs and Hugo output. (@NiklasRosenstein) (#359)
    • Preserve the first line's indentation in space-indented ReST code blocks. (issue #259, @NiklasRosenstein) (#360)
    • Allow bootstrapping YAML configuration in Poetry projects and warn when quick CLI options ignore local configuration. (@NiklasRosenstein) (#361)
    • Preserve relative indentation in Google-style docstring sections and render example code blocks correctly. (@NiklasRosenstein) (#363)
    • When rendering a page, rename reference-style link labels that more than one docstring defines, so their links no longer point to the first definition. Set namespace_reference_links: false to disable, or namespace_reference_links_in_objects: true to also rename labels in individually rendered objects (e.g. Novella). (issue #125, @NiklasRosenstein) (#364)
    • Derive the Hugo theme name from a Git URL by removing only the .git suffix and the hugo- prefix. (@bardrop) (#377)
    • --build without --site-dir now uses the default output directory of MkDocs or Hugo instead of crashing, and fails with a clear error for renderers that cannot build. A relative --site-dir is now resolved from the current directory for the mkdocs renderer, as it already was for hugo. (@NiklasRosenstein) The Markdown renderer creates missing parent directories of filename. (@NiklasRosenstein) --bootstrap readthedocs now writes a single .readthedocs.yaml that uses build.commands, replacing the setup based on readthedocs-custom-steps and the removed python.version setting. (@NiklasRosenstein) (#384)
    • Fix the automatic Hugo download for current Hugo releases: pick the right archive on ARM64, Windows (.zip) and BSD, fail with a clear message when a release has no archive for the platform (such as recent macOS releases), and fetch only the requested release instead of paging through all of them. (@NiklasRosenstein) (#385)

    Documentation

    • Fix links to docspec (@rafalkrupinski) (#337)
    • Restructure the documentation into getting started, guides, recipes and reference sections, shorten the README, document source linkers, and add a page listing deprecated and experimental features. (@NiklasRosenstein) (#384)

    Tests

    • Make the watchdog event handler test pass on every supported watchdog version. The file watcher works with watchdog 0.10 and newer, so no lower bound is added and Novella's watchdog<3 requirement can still be satisfied. (@NiklasRosenstein) (#379)

    Hygiene

    • Replace the Slap and Poetry development workflow with uv, mise tasks and towncrier changelog fragments. (@NiklasRosenstein) (#378)
    • Update the Docusaurus example to Docusaurus 3 and drop the unused types-deprecated development dependency. (@NiklasRosenstein) (#384)

    4.8.2 (2023-06-26)

    Fixes

    • Fix key aliases for pre-render and post-render keys in Hooks configuration (issue #291, @NiklasRosenstein) (#295)

    4.8.1 (2023-06-21)

    Improvements

    • Improve error message when no Pydoc Markdown configuration is found (@NiklasRosenstein) (#293)

    Fixes

    • Upgrade to Databind ^4.4.0 which fixes the "ForwardRef cannot be parameterized" error. (issue #292, @NiklasRosenstein) (#294)
    • Fix NoMatchingConverter for TypeHint(typing.List[~T_Page]) by making the Page type a concrete subclass of the old Page class now called GenericPage. This is needed to correctly define a recursive type that Databind can de/serialize. The Page type stays backwards compatible at runtime for cases when it is used as a generic (e.g. class MyPage(Page[MyPage]):) to not break existing code. (issue #291, @NiklasRosenstein) (#294)

    Tests

    • Add unit tests to deserialize Mkdocs and Hugo example configuration. (@NiklasRosenstein) (#294)

    4.8.0 (2023-05-28)

    Improvements

    • Upgrade from Databind ^1.5.0 to ^4.3.0`. This should not have any impact on the average Pydoc-Markdown user, however there may be some changes necessary for users that have been using the Pydoc-Markdown API beacuse of the changes to Databind between v1 and v4. However, these users should have pinned the major version of databind they're relying on, so this change is not considered breaking for Pydoc-Markdown. (@NiklasRosenstein) (#289)

    4.7.0 (2023-05-28)

    Improvements

    • Change PythonLoader.encoding default value from None (system default) to utf-8 (@NiklasRosenstein) (#282)
    • Support parsing all types of docstring formats that are supported by the docstring_parser module in SphinxProcessor, not just ReST (@hippalectryon-0) (#282)
    • Allow Pyyaml ^6.0 in addition to ^5.0 (@NiklasRosenstein) (#287)
    • Undeprecated YAML-based configuration for Pydoc-Markdown. (issue #286, @NiklasRosenstein) (#288)

    Fixes

    • No longer HTML-escape text in Markdown code blocks. (@hippalectryon-0) (#282)
    • Fix codeblocks rendering to maintain indentation as per the original docstring. (issue #169, @hippalectryon-0) (#283)

    Documentation

    • Update docs to inform user that mkdocs with mkdocs-material must be installed in Novella Usage guide. (issue #270, @NiklasRosenstein)

    • add explicit compatibility with Novella 0.2.x (>=0.1.10,<0.3.0) (@NiklasRosenstein)

    Fixes

    • fix interpreting Markdown in-document anchor links as cross references (issue #274, @NiklasRosenstein)
    • fix generated code for class signature with not base class and a metaclass parameter (issue #272, @NiklasRosenstein)

    Documentation

    4.6.0 (2022-03-02)

    Breaking changes

    • remove MarkdownRenderer.render_to_stream() from public api (@NiklasRosenstein) (#245)

    Features

    • add pydoc_markdown.interfaces.SingleObjectRenderer and use it in Novella @pydoc tag processor (@NiklasRosenstein) (#245)
    • add ApiSuite class and ResolverV2 which is used by the new @pydoc tag preprocessor when using Novella (@NiklasRosenstein) (#245)
    • MarkdownReferenceResolver now implements the new ResolverV2 interface and can resolve references globally (@NiklasRosenstein) (#245)
    • CrossRefProcessor now accepts a resolver_v2 argument to use instead of the resolver object passed through the Processor API (@NiklasRosenstein) (#245)
    • bring back formatting function, class and variable signatures with YAPF. (Tagging @lgeiger as the author because he was the original author of the feature in a previous version of Pydoc-Markdown, see https://github.com/NiklasRosenstein/pydoc-markdown/pull/78) (issue #244, @lgeiger) (#245)

    Improvements

    • do not render link to source for modules in MarkdownRenderer (@NiklasRosenstein) (#245)
    • Git source linkers now fall back to the SHA if the current branch is invalid (e.g. in a detached HEAD state) and logs a warning (@NiklasRosenstein)

    Fixes

    • fix forwarding of PluginBase.init() calls to sub-plugins in unittests and DocusaurusRenderer (@NiklasRosenstein) (#245)

    Documentation

    • docusaurus: Update plugin-content-docs config for docusarus@beta to not exclude files and folders with underscores. (issue #189, @chrisstetter) (#235)

    Hygiene

    • remove MarkdownRenderer.classdef_render_init_signature_if_needed option because it never worked to begin with (@NiklasRosenstein) (#245)

    • unset __PYENV_LAUNCHER__ environment variable for commands invoked via $.hooks.pre-render and $.hooks.post-render to avoid issues when the hook invokes a script installed into a different Python virtualenv than the virtualenv that is currently active in the terminal (@NiklasRosenstein)
